For local development, run the Laravel API and Nuxt frontend in separate terminals. You also need a reachable Firefly III instance and a personal access token for a development account.

## Prepare the tools

Use a current Node.js LTS release supported by the frontend's installed Nuxt version, plus Composer 2 and PHP with the extensions required by Composer. The application requires PHP 8.2 or later; development dependencies can require a newer version, so let `composer install` check your environment against the lockfile. Enable the PDO driver for your chosen database.

## Start the backend

In `back/`, copy `.env.example` to `.env` if you do not already have a local configuration. Set `FIREFLY_URL` to your development Firefly III address. The example selects SQLite; its default file is `back/database/data/database.sqlite`. Create the directory and an empty database file if they are missing, and make them writable by PHP.

Run these commands from `back/`:

```sh
composer install
php artisan key:generate
php artisan migrate
php artisan serve
```

Generate the app key when setting up a new installation. Run migrations against your development database. Keep the API terminal running and note the address Laravel prints.

## Start the frontend

In a second terminal, run from `front/`:

```sh
npm install
npm run dev
```

Open the address Nuxt prints. In Pico's setup screen, set the backend URL to the Laravel address including `/api`, for example `http://localhost:8000/api`, and enter the Firefly III token.

Load the category list to verify the connection. This exercises the browser, Pico API, and Firefly III together. A page rendering successfully only proves that the frontend started.

## Where to begin editing

Start with a simple entity such as categories. Read [Screens and forms](/guide/screens) before working on transaction entry, which combines more features and defaults.

The commands above start development servers. Deployment uses a built frontend and a production PHP server; the repository's Docker setup is the reference for assembling them. Optional Ramble services require additional configuration, introduced in [Assistant](/features/assistant).
