title: Docker
description: Run Pico as a complete app and understand the connection to Firefly III.

Docker is useful when you want a working Pico instance before changing its code. The container packages the frontend and backend behind one web address. Firefly III remains a separate service.

## Choose a starting point

Use `docker-compose.pico-simple.yml` from the repository when Firefly III is already running. The repository also includes `docker-compose.pico+firefly.yml` and `docker-compose.pico+firefly+importer.yml` for starting the services together.

Read and adjust the selected file before starting it. The values shipped in these examples are placeholders.

The two essential settings are **where Firefly III runs** and **where Pico keeps its database**. `FIREFLY_URL` must be reachable from the Pico container. The volume mounted at `/var/www/html/database/data` preserves Pico's extra fields, templates, and profiles between container replacements.

From the repository root, start the simple variant with:

```sh
docker compose -f docker-compose.pico-simple.yml up -d
```

Open the host port declared in that compose file. In this checkout, the simple example maps port `6976` to the container's web port.

## Connect your account

Create a personal access token in Firefly III, then enter it in Pico's setup screen. Pico uses that token to act on your Firefly III account. For a normal single-container installation, the default Pico backend URL already points to the right place.

There are two different addresses here: **the Pico backend URL** tells the browser where to send requests; **FIREFLY_URL** tells Pico's backend where to forward them. Keeping those roles separate makes connection problems easier to diagnose.

## Use this setup while developing

You can point a local frontend at a deployed Pico backend, or run both pieces locally using [From source](/installation/manual). Use a development Firefly III instance when trying changes that create or modify records: saving through Pico changes the connected instance.

Keep both databases in your backup plan. Firefly III's database contains the financial records; Pico's database contains the additions described in [Data and ownership](/guide/data).
