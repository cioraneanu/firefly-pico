Before adapting Pico, record a few sample transactions in a development account. The code is easier to understand once you have seen how accounts, categories, tags, templates, and profiles fit together.

## Organize a small example

An asset account represents where money is held. A category gives a transaction a broad purpose, such as Bills. Tags add more detail, such as Electricity or a particular trip. Pico can arrange tags into a hierarchy, helping users select a useful level of detail.

Create one account, a Bills category, and an Electricity tag. Configure the usual source account in transaction defaults. Then create a template for a bill whose amount varies.

Record the bill once through the form and once through assistant input. Check what the assistant fills, what remains editable, and how the saved transaction appears in the list. This is the workflow most adaptations should preserve.

## Add convenience gradually

A to-do tag can mark transactions that need later attention. A recurring transaction suits a fixed schedule. A template suits a transaction the user records when it happens. A profile groups defaults for a different context.

These features are most useful when they remove a repeated decision. You do not have to enable or configure every feature to have a useful Pico installation.

## Turn a workflow into an implementation question

If users keep choosing the same account, look at defaults. If they repeatedly fill the same group of fields, look at templates. If they struggle to read a list, look at its row component. If information needs to survive across devices, investigate backend storage.
