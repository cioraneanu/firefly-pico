Now that you know how a record reaches the browser, look at how Pico presents it. Most entity screens follow a familiar pair: a list for choosing an item and a form for creating or editing one.

## The page describes the feature

Nuxt maps files in `front/pages/` to routes. For categories, `list.vue` is the list and `[[id]].vue` serves both a new category and an existing one. Navigation constants keep links to these screens consistent elsewhere in the app.

The page selects its model, fields, toolbar, and feature-specific reactions. Shared composables handle the repeated lifecycle. `useForm()` coordinates form operations; `useList()` coordinates list behavior. Start with a nearby page using the same pattern when adding a screen.

![A page combines UI-kit fields with shared form or list behavior. The model connects that behavior to a transformer and repository, which reaches the Pico API.](/images/page-flow.svg)

## The fields edit one item

Form fields bind to the item being edited. `generateChildren()` exposes nested attributes as convenient bindings, so the page can connect an input to the name or icon without rewriting the same glue each time.

Use the existing UI-kit fields, validation helpers, save/delete buttons, and toolbar. They carry the app's layout and feedback conventions. A new field should feel like part of the same form before it introduces any new visual behavior.

## A save also changes what other screens know

After a successful save, the category page updates the category store. That is why a picker or list can show the new value without a full page reload. After deletion, the stored list removes the item. These reactions are part of completing the user action.

Some lists display a complete cached collection; others load pages from the API. Check which behavior the neighboring screen uses before copying its loading setup.

## Preserve the app's presentation

Pico has mobile and desktop layouts, chosen through `appStore.isDesktopLayout`. Reuse components that already handle this split. Styles belong in the shared theme files and helpers, with dark-theme behavior considered alongside light mode. Labels belong in the locale dictionaries.

Read `front/pages/categories/`, then `front/composables/useForm.js` and `useList.js` only as far as your change needs. [State and profiles](/guide/state) explains the shared data those pages rely on.
