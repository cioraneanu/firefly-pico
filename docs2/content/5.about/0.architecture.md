Pico separates the interaction layer from financial storage. The Nuxt app makes entry and browsing convenient; the Laravel API integrates with Firefly III and stores Pico's additions.

![Pico's browser app talks to its API, which connects financial records in Firefly III with additional records in Pico's database.](/images/system.svg)

## Frontend

`front/` is a Vue single-page application organized by Nuxt. Pages assemble UI-kit components and composables. Models connect forms to transformers and repositories. Pinia stores share entity collections and preferences, often with browser persistence.

Vant supplies the mobile UI foundation, with shared themes and separate desktop layout behavior. PWA support allows an installed-app experience. API requests still go through the Laravel backend.

## Backend

`back/routes/api.php` registers Pico resources and specialized Firefly-backed routes. Unmatched API paths fall through to the Firefly proxy. Proxied controllers commonly extend `BaseControllerFirefly`, which centralizes the request flow and enrichment of responses with declared extra fields.

Pico-owned resources, including transaction templates and profiles, use Pico's database. The default example configuration uses SQLite. Financial records remain in Firefly III, so restoring only one database does not restore the full combined experience.

## Identity and authorization

The browser supplies a Firefly III bearer token. Pico forwards it for Firefly requests and uses Firefly III identity checks in its own resource flows. Token hashing also participates in scoping Pico-owned data. There is no separate Pico sign-in account.

When extending a Pico-owned endpoint, follow its neighboring authorization and ownership checks. The existence of a proxy does not make an arbitrary new endpoint protected automatically. `back/app/Helpers/Helpers.php` and `back/app/Authorizations/` show the relevant existing machinery.

## Container runtime

The Docker setup exposes a single web port. Nginx routes API traffic to the backend and frontend traffic to the app. The deployment also configures the services needed for background work; inspect the Docker and compose files when changing that runtime.
