The assistant helps users fill transaction details with less typing. Begin with the shorthand assistant: it combines existing tags, categories, templates, and defaults to prepare the transaction form.

## Shorthand entry

The opening words identify a tag, category, or template through fuzzy search. An amount can follow, and additional text can supply a description. The result depends on the user's existing data and active profile.

| Input | Intended use |
| --- | --- |
| `electricity 23` | Find electricity and fill an amount of 23 |
| `elc 12*2+33` | Use a partial name and calculate the amount |
| `swim` | Apply the matching swimming template |

Users can also append their configured to-do marker to flag a transaction for later attention. The default marker is `!!`.

Think of this assistant as another way to fill the same form. When adapting it, keep the form's final values and the normal save path consistent. A shorthand match should not need its own separate transaction-storage logic.

## Ramble

This checkout also includes Ramble, which accepts less structured input and uses a configured language-model service to interpret transactions. Audio input additionally needs a transcription service. These requests go through Pico's backend; service configuration is described by the `ASSISTANT_*` settings in `back/.env.example` and the compose examples.

This is a separate path from local shorthand matching. Decide which experience you are changing before editing: improving template search and changing model interpretation belong in different places. The configured external service receives the input needed for interpretation or transcription, so its role should remain clear to users.

## Read the surrounding code

Start at the transaction-entry component that invokes the relevant assistant. For Ramble, follow the routes in `back/routes/api.php` to `AssistantController`. For shorthand, follow the frontend's assistant search and form integration. Test with recognizable tags and one template before adding more complex input.

[Profiles](/features/profiles) explains why the same entry can produce different defaults in different contexts.
