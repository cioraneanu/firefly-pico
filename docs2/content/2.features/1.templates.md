title: Templates
description: Reuse the familiar parts of a transaction while leaving room for what changes.

A template is a saved starting point for a transaction. It can fill several fields at once, so you only enter the details that change each time.

For an electricity bill, the category, tags, and source account may stay the same while the amount changes. A template keeps the familiar values together. Applying it fills the form; you can review and edit the result before saving.

## Templates and recurring transactions

Choose a template when the user decides when to record the transaction. Choose a recurring transaction when a schedule should drive it. Both reduce repetition, but a template is a form shortcut rather than a schedule.

Pico includes recurrence screens as well as template screens, so choose the workflow that matches how the transaction happens.

## How templates connect to the assistant

A template can have multiple names, allowing different words to select the same saved values. The assistant searches these names alongside tags and categories. That makes the template useful without navigating away from transaction entry.

For example, a swimming template can supply the usual account and category. Typing its name lets the user start from those defaults and enter today's price.

## Adapting templates

Templates are Pico-owned records. Their storage and API live in `back/`, while the form and data conversion live in `front/`. If you add a transaction field and want templates to remember it, check both the template's saved shape and the point where it is applied to a transaction.

Start with `front/models/TransactionTemplate.js` and the matching repository and transformer. Follow their usage into the form for the exact supported fields.
