---
title: Localization
description: Keep app labels, component messages, and dates in the same language.
---

Pico's translations have three cooperating parts: the app's own labels, Vant's built-in UI messages, and date-fns date wording. A complete language setup connects all three.

## Change an existing label

Find its key in `front/i18n/locales/`. Components refer to these keys rather than embedding text directly. Keep the meaning consistent across the ten locale files, and preserve placeholders used to insert values.

When adding a feature, add its keys to every supported locale. Choose wording that describes the user's action rather than the implementation. Check the actual screen: a correct translation can still be too long for a compact mobile control.

## Add a language

Use an existing language as the model. Add its dictionary under `front/i18n/locales/` and register it in `front/i18n/index.js`. Add the corresponding flag asset under `front/assets/icons/flags/` following the current picker convention.

Then connect the language in `front/plugins/plugin-vant.js` and `front/plugins/plugin-date-fns.js`. This makes built-in controls and date wording follow the selected language alongside Pico's own labels.

## Verify the whole experience

Parse the JSON, switch to the language, and inspect a form, a list, and a date control. Check interpolated values and empty states as well as headings. Include the changed language in both mobile and desktop inspection when layout is affected.

The important outcome is a coherent experience: choosing a language should carry through the controls people use to complete a task.
